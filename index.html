Capstone Architecture Breakdown

Deepfake Shield — In-Browser Forensics Architecture

Why run detection in the browser?

Most deepfake detection tools send user video to remote cloud servers. For high-resolution streams, that introduces bandwidth lag, recurring GPU server bills, and real privacy concerns with transmitting webcam feeds. I built Deepfake Shield to evaluate frames directly in the browser with TensorFlow.js and WebGL, so user video never leaves their local device.

The 8 Detection Signals

1. Landmark Mesh MediaPipe Face Mesh tracks 468 3D landmark points per frame.
2. Blink Dynamics (EAR) Calculates Eye Aspect Ratio over consecutive frames to catch unnatural blink cadence.
3. Facial Symmetry Checks for irregular geometric warping across mouth, cheeks, and jawline movements.
4. Head Pose Alignment Measures Euler angles (Pitch, Yaw, Roll) to verify natural 3D depth and angle changes.
5. Micro-Pulse (rPPG) Analyzes subtle frame-by-frame skin color changes from capillary blood flow.
6. Frequency Noise Detects checkerboard pixel artifacts and spectral anomalies left by generative models.
7. Temporal Jitter Monitors frame boundary transitions to catch facial blending seams and flickering.
8. CNN Classification Feeds computed facial feature vectors into a lightweight TensorFlow.js model via WebGL.

Smooth 30+ FPS Execution

Running multi-signal computer vision in a single browser thread can easily freeze the tab. I separated video decoding from landmark inference using requestAnimationFrame and offloaded vector calculations to the GPU via WebGL shaders, maintaining smooth 30+ FPS playback on ordinary laptops.

Telemetry & Reports

The interface provides a live telemetry HUD over the video stream, with one-click export to PDF, CSV, and Markdown for documentation.
